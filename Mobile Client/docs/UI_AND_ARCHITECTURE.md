# UI 与客户端开发说明

## 视觉规范

“微光”为当前工作名称。森林绿强调色 `#285A45`，背景 `#F4F6F3`，卡片白色，正文 `#1C3029`，次级文字 `#52675D`。深色模式对应墨绿背景和浅绿强调色，定义集中于 `ui/Theme.kt`。

导航选中背景使用浅绿 `#DCEADF`，深色模式使用 `#354D3E`。状态栏和系统导航图标随应用主题切换。创建或加入测试组后主动收起输入焦点，给结果区域留出空间。

页面水平边距 22 dp，普通卡片圆角 24 dp，主要按钮高度至少 48 dp。正文 16 sp，辅助文字采用 Material 字体样式。所有页面使用系统字体，随系统字体缩放。组件使用 Compose 语义和有名称的图标操作。

主页面为首页、线索、设备、我的。组管理为二级页面。截图识别后进入可展开的核对弹层，先检查原图和文字，再选择上传。登录失效统一回到登录页。网络错误显示 Snackbar 并保留本地内容。

## 页面与实现

| 页面 | 实现与行为 |
|---|---|
| 登录与注册 | 输入校验、密码隐藏、服务地址配置、离线体验入口 |
| 首页 | 建议卡片、来源展开、采纳忽略、最近线索、云端同步 |
| 线索 | 图片选择、外部图片分享、手动记录、日历和位置导入、纠错、删除、共享 |
| 设备 | 实际手机型号、一次性权限申请、系统授权入口、穿戴通知测试 |
| 我的 | 当前账号、测试组入口、跟随系统与深浅主题、连接说明、退出 |
| 测试组 | 创建、邀请码加入、成员列表、组长生成邀请码及移除成员、共享快照 |
| 腕上设计 | 明确标注为设计态，展示未来独立手表应用的卡片规格 |

## 数据流

`Screens → AppViewModel → Repository → Room / ApiClient / SessionStore`。

`CaptureService` 负责 OCR 与系统数据入口。`SyncWorker` 负责有网络时重试允许上传的数据。界面订阅 Room Flow，来源记录与展示状态在数据库中持久化。

网络调用和会话刷新在 Repository 的互斥锁内串行执行，避免并发刷新和退出切换产生错号请求。所有本地实体使用 `服务地址|用户ID` 作为账户分区，UI 同时过滤当前账户，避免 Flow 切换时显示上一账号的缓存。

用户修改已同步线索时，版本加 1，并进入待上传。用户删除线索时先隐藏本地记录，若需要云端删除则保留删除标记等待成功后移除。来源变化会使相关建议失效。

## 开发入口

页面实现集中于 `ui/Screens.kt`。当前单工程按职责分包，未来页面增多时可将每个 Screen 拆为文件。通用 Panel、Mark、Note 与主题已复用，避免不同页面出现不同视觉标准。

新增数据来源需要定义采集字段、权限、失败状态和来源标识，然后经过同一核对及保存入口。新增卡片需要同时更新后端 schema、客户端允许类型、专属渲染和回归测试。

当前 Android 10 为最低版本，编译和目标 SDK 为 35。以后更新目标版本时应重新测试权限、边到边布局、后台限制与通知展示。首发只集成中文文字识别库，安装体积以实际构建为准。
