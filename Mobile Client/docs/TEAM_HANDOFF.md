# 微光团队对接要求 · 协议 v1

本文以工程内真实实现为准。手机端已完成数据入口、标准化记录、账号与测试组页面、建议卡片和反馈。云端模型与设备 SDK 可以独立替换接入。

| 负责方 | 应交付内容 | 联调完成条件 |
|---|---|---|
| 手机端 | 可安装 APK、主题组件、数据来源、上传队列、卡片与账号组管理 | 完成 README 的双账号演示 |

| OPPO/穿戴 | 型号及地区系统版本、SDK 文档和授权、能力清单、最小样例 | 按通知、健康读取、按钮回传分别真机验收 |

## 通信与身份

HTTP JSON，编码 UTF-8，基路径 `/v1`。发布版使用 HTTPS。受保护接口需要 `Authorization: Bearer <access_token>`。服务端从令牌识别用户，客户端不提交可决定数据归属的 `user_id`。

账号名为 3–32 位字母、数字和下划线，服务端统一小写。密码长度 8–128，服务端使用 Argon2id。访问令牌有效期 15 分钟，刷新令牌 7 天。每次刷新轮换两个令牌并使旧令牌失效。退出撤销当前会话，不影响另一台设备的独立会话。

手机端加密保存会话，在会话锁内串行刷新，避免并发请求重复使用旧刷新令牌。断网退出会删除本机凭据并停止该用户上传任务，同时告知用户服务端撤销尚未完成。用户重新登录后才继续上传未完成记录。

## 实际接口清单

| 方法与路径 | 输入或作用 |
|---|---|
| `GET /health` | 返回状态、协议版本、当前建议提供者 |
| `POST /v1/auth/register` | `username, password`，返回会话和用户 |
| `POST /v1/auth/login` | 同上 |
| `POST /v1/auth/refresh` | `refresh_token`，返回轮换会话 |
| `POST /v1/auth/logout` | 撤销当前会话 |
| `GET /v1/me` | 当前用户 `id, username` |
| `GET /v1/groups` | 当前用户参与的组，响应 `{items: [...]}` |
| `POST /v1/groups` | `name`，创建组并成为 owner |
| `POST /v1/groups/join` | `code`，加入组 |
| `GET /v1/groups/{id}` | 组名、成员、明确共享的文字快照 |
| `POST /v1/groups/{id}/invites` | 仅 owner 可生成邀请码 |
| `DELETE /v1/groups/{id}/members/{userId}` | 仅 owner 可移除普通成员 |
| `POST /v1/events` | 单条事件新增、幂等重试或版本更新 |
| `GET /v1/events` | 当前用户全部事件，响应 `{items: [...]}` |
| `DELETE /v1/events/{eventId}` | 幂等删除本人事件及其组内共享 |
| `POST /v1/decisions/generate` | `request_id, event_ids`，返回单张建议 |
| `GET /v1/decisions` | 本人的建议与最新失效、反馈状态 |
| `PUT /v1/decisions/{id}/feedback` | `action, reason`，幂等保存最终反馈 |
| `POST /v1/groups/{id}/shares` | `event_id`，明确共享本人文字快照 |
| `DELETE /v1/groups/{id}/shares/{eventId}` | 撤回本人在该组的共享 |

本版列表返回完整集合。若云端改为分页，须与手机端一起升级拉取逻辑，不能直接截断响应。

## 线索协议

```json
{
  "schema_version": 1,
  "event_id": "35ab0888-5050-4402-98d7-7fd168f97c01",
  "revision": 1,
  "event_type": "message",
  "source_kind": "screenshot_ocr",
  "captured_at": "2026-11-08T09:36:00+08:00",
  "occurred_at": null,
  "timezone": "Asia/Shanghai",
  "review_status": "confirmed",
  "payload": {"text": "明天18:30在A302讨论项目"}
}
```

`event_id` 唯一标识一条记录，`event_type` 表示语义类型，`source_kind` 表示采集渠道。它们分别承担不同职责。

- 已实现的 `event_type` 为 `message / schedule / location / note`。
- 已实现的 `source_kind` 为 `screenshot_ocr / calendar / location / manual`。
- `captured_at` 是采集时间，`occurred_at` 是已明确的发生时间。两个字段都使用带时区的 ISO 8601，未知发生时间为 null。
- 截图中的“明天”不能仅凭截图导入时间确定。客户端保留原文，用户可以补充具体时间，当前规则会对相对日期发出追问。
- `payload.text` 为 1–10000 字符。位置首版以可读坐标、精度和采样时间存入文字字段，后续结构化位置需要双方共同升级 schema。
- OCR 原图只在核对界面显示，离开后只持久化确认文字，不上传图像。
- 线索新增 `revision=1`。同用户同 ID 同版本同内容重复上传返回成功。更新必须为当前服务端版本加 1，其余情况返回 409。
- 同一个事件来自多次不同截图时有不同 UUID。本版幂等处理同条记录的网络重试，语义层面的重复消息合并留给决策场景设计。

成功响应为 `{"event_id":"...","revision":1,"status":"synced"}`。手机端内部的 `accountKey` 和 `syncState` 不进入云端业务协议。

## 建议协议与模型替换

替换点是 `backend/main.py` 中的 `rule_decision(events)`。目前返回 `provider=rule_demo`，只是明确标注的联调规则。模型接入后提供自己的 provider 标识，并按 `decision.schema.json` 校验。

```json
{
  "schema_version": 1,
  "decision_id": "d9c80d3a-7494-4618-aef3-410b5d691977",
  "provider": "rule_demo",
  "card_type": "question",
  "title": "先确认线索中的具体时间",
  "summary": "材料包含相对日期，请核对具体日期后再安排。",
  "created_at": 1794096000,
  "expires_at": 1794182400,
  "status": "active",
  "evidence_ids": ["35ab0888-5050-4402-98d7-7fd168f97c01"],
  "evidence": [{"event_id":"35ab0888-5050-4402-98d7-7fd168f97c01","revision":1}],
  "actions": [{"type":"accepted","label":"采纳"},{"type":"dismissed","label":"忽略"}]
}
```

当前渲染 `summary / question` 两类卡片，分别表达摘要与待确认问题。`reminder / options` 为后续扩展方向，须补充专用字段与 UI 后启用。未知版本或类型显示明确的兼容提示。

时间戳 `created_at / expires_at` 使用 Unix 秒，事件时间使用 ISO 8601，两者在接口中已明确区分。`GET /decisions` 额外返回 `feedback`，为 null、accepted 或 dismissed。

模型接入须满足以下行为。

1. 依据只能引用当前用户传入并允许使用的事件，禁止跨用户检索原始材料。
2. 截图和聊天原文按待分析数据处理，里面出现的指令不能提升为系统工具权限。
3. 结果严格校验字段、长度、动作枚举和证据引用。模型返回任意 URL、脚本、HTML 或应用操作时不得直接执行。
4. 缺失数据通过 `question` 追问。未经核验的推断不能变成确定事实或伪造置信度。
5. 依据删除、版本变化或超过有效期后，建议标记 `stale / expired` 并拒绝继续采纳。
6. 同一 `request_id` 重试返回同一建议。更换输入必须使用新请求 ID。若改为异步任务，需新增任务状态协议并同步修改手机端。
7. 当前动作仅记录反馈，外部日历编辑、发消息、支付与退订需要未来专用动作和用户确认流程。

## 测试组规则

组长与成员分别为 `owner / member`。加入组不会开放个人聊天、定位或日历。组长也不能读取未共享的原始线索。

邀请码是服务端生成的 10 位十六进制字符串，有效 24 小时，最多使用 5 次。同一用户并发或重复加入只消耗一次名额。邀请按哈希保存，普通成员无权生成邀请。

共享发送所选事件的文字快照。之后编辑原始事件不会悄悄改写已共享快照，再次明确共享才更新快照。撤回共享、删除原事件或移除成员会删除相应共享。客户端需重新打开组详情获取最新状态，当前没有实时推送。

## 错误与重试

统一业务错误响应为 `{"detail":"可展示的中文原因"}`。Pydantic 格式校验错误使用数组形式 detail，客户端会展示通用校验提示。

| 状态 | 处理 |
|---|---|
| 400 | 输入不符合当前业务条件 |
| 401 | 手机端尝试刷新一次，刷新失败退出登录态 |
| 403 | 当前用户没有组或资源操作权限 |
| 404 | 资源不存在，或不属于当前用户 |
| 409 | 版本冲突、过期建议、重复账号等需要用户处理 |
| 422 | 字段、时间格式、枚举、长度校验失败 |
| 429 | 登录、入组或刷新限流，稍后重试 |
| 5xx / 网络失败 | 保留待处理记录，后台指数退避补传 |

更新结果不确定时，必须使用相同 ID、版本和内容重试。待同步或等待重试中的记录暂停纠错，避免第一次请求已成功但客户端误用相同版本发送不同内容。冲突记录可通过手动同步恢复云端版本，恢复前应复制需保留的本地内容。

## 穿戴设备对接表

设备同学需要填完以下表再开始具体 SDK 实现。

| 项目 | 需要填写 |
|---|---|
| 设备身份 | 品牌、型号、地区版本、系统版本、配套手机型号 |
| 通知 | 能否转发本应用通知、是否支持按钮、断连行为 |
| 健康数据 | 可读字段、单位、授权入口、更新频率、历史查询范围 |
| 数据依据 | 采样时间、同步时间、缺失标记、数据来源 |
| 应用能力 | 能否安装独立应用、屏幕尺寸、通信机制、是否依赖 GMS |
| SDK | 文档、版本、初始化样例、账号与应用审核要求 |
| 验收 | 真机照片或录屏、请求与回传记录、耗电观察、已知问题 |

手机“发送测试通知”只证明系统接受了通知发送调用。腕上送达由人工核对，页面不会伪装显示“手表已连接”。健康服务与腕上按钮回传是独立能力。

## 协作提交要求

接口变更应附更新的 OpenAPI、请求响应样例、兼容说明和对应回归测试。涉及协议变更先更新 schema_version，并约定旧版本处理方式。真实生产凭据不提交到仓库。

建议的联调提交包含一次完整过程的录屏、设备及系统版本、后端提交版本、成功与失败请求的脱敏记录、复现步骤。错误记录保留 request_id 与 event_id，避免输出聊天正文、密码或令牌。

手机端本版直接使用 OkHttp 映射 JSON，减少联调依赖。后端默认 SQLite，正式多实例部署迁移数据库与限流时保持本文事务及隔离语义。
