## 模拟器实际走过的流程

Android15 / API35 / x86_64 / emulator-5560，2个虚拟CPU、2GB内存，WHPX，720×1280显示。

1. 注册独立测试账号并创建信息整理事项。
2. 用真实 PP-OCRv6 tiny 在模拟器内识别合成聊天图：“周五在A302讨论项目”“记得带电脑”。
3. 验证发言人、消息时间及归一化坐标存在，调用共享去重模块；重复输入不再生成第二条材料。
4. 主机实际移除 `adb reverse tcp:8765`，请求因网络连接失败；Room保留结构化原文、待上传状态及固定任务请求ID。
5. 恢复转发到独立测试网关8876，补传后创建唯一Agent任务；重复同步仍为同一任务ID。
6. 服务端保留微信包名、聊天标题、发言人、消息时间及坐标，未将数据拍平成普通文字。
7. 在Compose页面打开候选，确认前正式版本v0；用户点击确认后，正式版本更新到v1。
8. 从页面关闭自动记录，核对事项自动记录授权已移除，并保存截图。

模型生成在本轮设备用例使用mock，以确定性验证接口与状态流程；OCR使用真实ONNX权重。公网真实模型另行复核，没有将mock结果作为语义准确率证据。

## 公网复核和部署

- 新网关代码已同步阿里云，替换前停服备份代码与数据，随后恢复systemd服务。未修改既有账号数据或模型密钥。
- 入口：`https://agent.qwertyuiopasdf.asia`。
- 通过认证上传模拟器识别出的同一份结构化材料，创建cloud-v1事项任务；模型返回候选后，确认使正式版本从0变为1，退出并再次登录后仍可读取。
- 首轮真实模型调用返回HTTP429；之后最小请求恢复200，完整复核重试通过。未切换为mock或其他模型掩盖失败。
- 仅清理了本轮两个随机合成公网账号及对应工作区；本机测试数据保留在artifacts便于核查。
- 云端仍为轻量词法记忆，不加载Qwen；本次没有新增云端OCR或模型训练依赖。
