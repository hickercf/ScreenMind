# 记忆与 SuperAgent 研究适配 · v0.5 · 2026-11-11

## 本轮结论

已经完成第一轮机制实现、作者代码检查、小规模对照实验和产品接入。**没有完成 SimpleMem 全文实验复现，不能声称达到论文 LoCoMo 指标；也没有部署完整 DeepSeek Harness 原型。**

产品运行方式为：手机授权材料 → 事项关联 → Router → 主 SubAgent → 当前事项历史检索 → 可选只读证据审阅 Agent → 候选输出 → 用户确认。正式状态仍只有框架能够提交，派生记忆和辅助 Agent 均无状态写权限。

## 记忆实现

1. 原始证据、正式状态和派生记忆分层；每项数据绑定 owner、work_id 和 source_ref。
2. `StructuredExtractor` 在单个来源窗口内抽取最多6个单元，保留陈述、逐字引用、实体和不确定标记。重复单元去重，相邻相关细节可合并；模型引用必须存在于原文。**逐字引用校验不能证明陈述语义完全正确**，因此派生结果仅作为检索提示。
3. `IntentPlanner` 将问题拆为最多3个查询及有界关键词/实体提示，选择最多12个结果。失败或超时退回原查询。
4. 轻量 `structured` 模式使用 SQLite 中的记忆条目及中文词法/实体检索，不调用向量模型；词法排序为二值词频、长度归一化与 IDF 加权，不能等同于作者原版 BM25 实现。
5. `hybrid` 保留已有 LanceDB、Qwen 或明确标注的 hash-demo 通道。真实 Qwen 权重在当前电脑尚不完整，本轮没有真实语义向量结果。
6. 找到条目后回查授权原文，组装当前正式状态、本轮材料和历史；不会把摘要作为已确认事实。每次构建和计划记录调用用量，失败尝试也留审计信息；缺失 usage 明确标记，不能当成零消耗。
7. 删除、重建和迟到结果继续使用来源白名单与 generation 校验；历史总预算仍为12000字符，未索引/失败条目有原文补充通道。

`structured` 是运行模式名称，并不表示一定启用了模型抽取。配合 `raw` 时，它是无向量、无额外模型构建开销的原文检索。

## SuperAgent 的辅助委派

新增 `delegate_evidence_review`：主 Agent 明确选择当前上下文中最多12个来源，交给独立的只读模型调用。辅助 Agent 只能返回带逐字引用的发现与缺失信息，不能访问数据库、执行工具、递归委派或确认计划。

- Party、Schedule 和绑定事项的信息整理均可注册这一能力。
- 输入总预算16000字符；模型 HTTP 超时沿用项目配置并封顶60秒，委派最多65秒；每轮最多两个不同审阅请求，整体仍受父任务步数/时间预算限制。线上首次验收发现20秒读取超时过短，已调整；失败记录仅保存异常类型，不输出密钥或原文。
- 同轮相同请求成功后复用结果；父任务取消、来源删除或正式版本变化后，结果不得提交。
- 持久化父子关联、输入、状态、结果和用量；重启时进行中的委派丢弃，父任务按已有恢复机制重新执行。
- 取消等待可能不能取消已发出的模型请求，仍可能产生一次费用；辅助线程没有写状态的能力。
- 主能力负责汇总和提交候选，用户确认仍是独立步骤。它是一层有边界的协作，不是无限自主团队。

## 固定样例实验

数据文件：`examples/research-memory-cases.json`，SHA256：`7e18dd9c847bf469d15d3072f7415feea0c305cf99143f124b2704f5b50eb4dd`。

2个事项（Party、Schedule），共36条原始材料、4个问题、6个必需来源引用。每个事项将重要材料放在14条干扰材料之前，专门覆盖“超过最近10条”的情况。因此该集合偏向长历史查找，不代表日常用户分布。

| 方法 | 组装上下文中必需来源召回 | 所有来源齐全的问题数 | 平均历史字符数 | 额外记忆/规划模型调用 |
|---|---:|---:|---:|---:|
| 完整历史 | 6/6 | 4/4 | 6406 | 0 |
| 基础近期历史（最近10条） | 0/6 | 0/4 | 3476 | 0 |
| 原文词法检索＋近期后备 | 6/6 | 4/4 | 6408 | 0 |
| 结构化抽取＋意图规划＋近期后备 | 6/6 | 4/4 | 7328 | 40 |

完整历史对照预算为200000字符；其余均为12000字符。全部方法保留同一份当前状态与当前输入。指标衡量**证据是否被带入上下文**，没有评估模型最终答案准确率，也没有证明检索排序质量。

最终实验的结构化构建调用36次：15115输入 token、15105输出 token；规划调用4次：1383输入 token、1041输出 token，共32644 token。所有调用都有服务端 usage，36条构建均成功。这仅统计记忆构建和检索规划，不包含下游主 Agent 生成答案的消耗。模型为 deepseek-flash；不将 token 数换算为未经核实的费用。

结果：相对近期历史，检索补回了旧证据；相对原文检索，当前结构化/规划适配**没有显示额外召回收益，也没有减少上下文**。不能把这里的4/4写成产品100%准确率或论文效果。完整机器可读结果见 `research/memory-v1-results.json`。

## 产品选择与配置

本轮产品接入选择低开销模式：

```ini
SCREENMIND_MEMORY_MODE=structured
SCREENMIND_MEMORY_EXTRACTOR=raw
SCREENMIND_MEMORY_PLANNING=false
SCREENMIND_EVIDENCE_REVIEW=true
```

开发环境比较论文思路时：

```ini
SCREENMIND_MEMORY_MODE=structured
SCREENMIND_MEMORY_EXTRACTOR=structured
SCREENMIND_MEMORY_PLANNING=true
SCREENMIND_EVIDENCE_REVIEW=true
```

两种配置都需要真实模型配置才能启用审阅能力；实验模式还会异步调用模型构建记忆。切换抽取器后应显式重建相关事项记忆；源码默认仍是 basic、审阅关闭。

手机网关新增认证接口：

| 接口（前缀 `/v1/agent`） | 用途 |
|---|---|
| `GET /works/{id}/memory-index` | 构建进度 |
| `POST /works/{id}/memory-index/rebuild` | 重建派生记忆，不改正式状态 |
| `GET /works/{id}/memories?limit=20&after=...` | 分页查看当前配置的有效记忆条目 |
| `GET /tasks/{id}/delegations` | 查看辅助执行记录 |

现有 APP 可以通过原有任务入口使用服务端增强能力，不需重新安装 APK；手机原生记忆管理页面本轮未新增。

## 验收记录（2026-11-11）

- 云端完整自动测试：67项通过；手机网关后端测试：27项通过。调整审阅超时后补跑研究记忆与第二阶段测试。

- 本次合成日程的候选生成耗时36.22秒，辅助审阅成功；这是单次功能验证，不是延迟基准或并发容量结论。
- 日历结果为成功生成 ICS 文件，尚未代表已导入手机系统日历。APP 原生界面及真实用户试用不在本轮验收范围。
- 前两次线上审阅失败，后一轮审计确认 `ReadTimeout`；取消独立20秒限制后流程通过。后续仍需监测模型服务延迟。
