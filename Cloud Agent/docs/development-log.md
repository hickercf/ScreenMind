# ScreenMind 云端开发日志

本日志记录云端 Agent、记忆、接口、验证和部署决策。2026-11-18 首次集中补录。历史条目使用验收文档记载的日期，GitHub 链接提供相应版本的提交证据。若实际开发日期无法追溯，标为补记或记录可核实的日期范围。

以后在同一份文件顶部追加当天记录，随相关代码一起提交或由团队在 GitHub 上提 PR。每条记录写清日期、改动或决策、验证环境和结果、待确认事项。实测注明真实模型或模拟、真实或合成材料以及样本数。部署另写目标版本和健康检查，未发布的代码标为本地验证。日志仅引用脱敏证据。

## 2026-11-18 · 赛事验收与 Party 行动反馈

- Party 职责增加完成状态，旧记录默认为待办。成员退出后的候选展示按确定人数估算的人均变化。完成证据生成独立候选，由用户确认后写入正式状态。
- 本地真实 deepseek-flash 用合成材料跑通初始计划、模糊退出、明确退出、交接、实际完成，正式版本最后到 v3。云端回归 71 项通过，之后补测两处历史场地的原文能在超出近期窗口后被词法检索找回。
- 固定同一份旧计划和材料，比较通用助手、云端关闭审阅、云端提供审阅工具。三个配置在这一次测试均满足 5 项检查，分别用时 9.33、6.80、43.70 秒。提供审阅工具的配置实际发起一次辅助调用，调用失败，主 Agent 仍能生成正确候选。本次未测出辅助审阅收益。
- 本地验证。真实用户跨天试用及正式发布仍待验收。复现指令与评分口径见[竞赛验收记录](contest-validation.md)。

## 2026-11-11 · 记忆机制、辅助委派和部署 · 补记

- 增加可追溯的 SQLite 词法检索、结构化抽取和查询规划实验模式。辅助 Agent 审阅限于显式传入的来源，正式状态仍走用户确认。
- SimpleMem 机制对照使用 4 道合成题，词法与抽取加规划均找齐 6 组必要来源，后者增加 40 次调用。Qwen 本机实验的 32 个有答案问题，取前 3 条时找齐证据分别为向量 32/32、词法 26/32，当前非量化 Qwen 的峰值常驻内存为 3.73 GiB，2 GB 服务器保留轻量词法方案。两组统计测量证据召回。
- Ubuntu 部署完成 HTTPS、systemd 拉起、备份恢复与真实模型验证。
- [记忆与委派记录](research-reproduction.md) · [Qwen 实测](qwen-local-benchmark.md) · [阿里云验收](../../Mobile%20Client/docs/ALIYUN_DEPLOYMENT_REPORT.md) · [云端实现提交](https://github.com/hickercf/ScreenMind/commit/e96e9b6808e50b5fa9a5e600ea255435d0f356b0)。
